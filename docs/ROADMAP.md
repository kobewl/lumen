# Lumen：从 v0.01.1 到 v1.0.0

## 产品目标

成为单用户、以飞书为主要入口的个人事务助手，把聊天、个人记忆、知识笔记、目标计划、任务执行、到时提醒和复盘连成一个闭环。让用户知道它记住了什么、计划了什么、实际改变了什么，也能纠正、撤销和迁移自己的数据。

“更好用”是设计目标，不是假定的竞品胜出结论。v1.0 定义为下列个人事务场景完整可用，并不等于一个拥有所有外部服务账号权限的万能执行器。

## 研究与选择

2026-10-01 阅读的原始资料：

- [OpenClaw README](https://github.com/openclaw/openclaw/blob/main/README.md)：自托管网关、渠道、工具与插件。借鉴渠道解耦和显式权限边界。
- [Letta README](https://github.com/letta-ai/letta/blob/main/README.md)：有状态 Agent 与持久记忆。借鉴把记忆当产品对象，而非把全部聊天永久塞进提示词。
- [LangGraph README](https://github.com/langchain-ai/langgraph/blob/main/README.md)：持久执行、人工介入、短期与长期记忆、可观察性。借鉴事务、执行回执与确认节点；当前单用户体量不引入整套框架。

Lumen 的设计重点是个人事务闭环、轻部署和可纠正性。保持 Python、SQLite、DeepSeek 兼容接口和飞书长连接，避免把已跑通的部署再换一遍。

## 必须完成的用户场景

1. 在飞书聊天，明确记住偏好；纠正同一事实；忘记后旧信息不回流。
2. 候选记忆必须确认才进入个性化上下文；临时信息可以设有效期。
3. 给出目标，拿到可编辑计划草稿；确认后形成项目和任务；能查询完成与未完成。
4. 任务可设截止、优先级和独立提醒，完成后关联提醒停止；任务可改期。
5. 保存一个想法或资料为笔记，随后按关键词找回；回答引用实际记录。
6. 一次、每天、每周、工作日、月度任务能够执行；提醒可暂停、改内容、稍后再提醒。
7. 用户启用每日简报/每周复盘后按时发送；无模型时基本事务与确定性简报可用。
8. 查看最近操作并撤销可恢复的误操作；出现后续冲突时拒绝覆盖。
9. 模型不可用、飞书断网、执行被中断时给出真实状态，不声称成功。
10. 导出个人数据；一致性备份；离线恢复后验证数据库完整性。
11. 在手机网页上管理同一套数据，配置凭据不暴露，能查看版本和渠道状态。

## v1.0 的范围边界

单用户；飞书个人文本消息与网页；模型 API；本地个人事务数据。普通提醒和事务快捷命令不依赖模型。计划确认、候选记忆确认、撤销由显式用户操作触发。

浏览器自动操作、语音识别、邮箱/日历/支付账号、任意 Shell、第三方 MCP 市场、多用户权限系统留在后续版本。这些需要额外账号接入和各自的安全/可靠性验收，不用空壳占位或虚假成功来凑“完全体”。

## 发布门槛

旧版测试持续通过；新增关键功能和失败路径有自动化测试；浏览器真实操作通过；旧 SQLite 兼容升级、备份恢复通过；全部 Git 文件敏感信息扫描通过。真实 DeepSeek/飞书在已有部署环境再验收，测试环境的模拟接口不能算真实平台联调。
