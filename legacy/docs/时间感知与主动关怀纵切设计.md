# 时间感知与主动关怀纵切设计

> 状态：架构验收后的**指定纵切**，不允许自由扩展。范围外的项（新增 Agent、A2A、
> 通用工具框架、真实飞书发送默认开启等）明确不做。工具层（`tooling`/`tools`）
> 只做最小扩展，不重写。

## 0. 要修的两个真问题

1. **"中午说早呀"**：当前可信时间只是一个可选工具（`get_current_time`），
   模型不调它就没有时间；`agent.go` 各处直接 `time.Now`，Synthesizer 拿到的
   提示词里根本没有时间。闲聊里的时段问候（早上好/下午好）完全靠模型运气。
2. **主动关怀没有落地路径**：模型有"主动性"人设，但没有任何受控的出口——
   要么永远不说，要么无法保证"少打扰、有依据、可审计"。

## 1. 数据模型

### TemporalContext（每轮唯一，代码生成）

```go
package temporal // server/internal/temporal

type Clock interface{ Now() time.Time }        // SystemClock / FixedClock（测试与本地验收）
type Context struct {
    Now     time.Time        // 已转换到本地时区（Asia/Shanghai）
    Loc     *time.Location
    Date    string           // 2006-01-02
    Weekday string           // 周五
    DayPart string           // 早上 5-9 / 上午 9-12 / 中午 12-14 / 下午 14-18 / 晚上 18-23 / 深夜其余
}
func Build(c Clock, loc *time.Location) Context
func (c Context) Valid() bool
```

一轮 = 一个 Context 对象，在装配根（`QAService.Handle`）由注入的 Clock 生成**一次**，
随后传给：Planner 提示词、Synthesizer 提示词、事实兜底、工具执行器（进而到所有
需要当前时间的工具）。任何一层都**不允许**自行调用 `time.Now`：
`tooling.Executor.Run` 要求 `RunInfo.Temporal.Valid()`，不满足时 fail-closed
（整轮拒绝，理由"缺少可信时间上下文"）——"没有可信时间"从一个约定变成结构保证。

### tooling 的最小扩展（不改治理逻辑）

- `tooling.RunInfo{Actor, Temporal, TurnSource}` 取代 `Run` 的 `actor string` 参数；
- `tooling.Invocation` 增加 `Temporal`（工具读时间用）与 `TurnSource` 字段。

### 本轮用户消息来源（修审查缺口：偏好不得被无关记录背书）

- Agent 在每轮生成 `TurnSource = "u_" + ulid`（代码生成，模型不可伪造，
  在参数 schema 里根本不存在，给了会被策略拒绝）；
- 飞书路径下 `RecordConversation` 用它作 conversations 行 ID，因此可回溯核对；
- `save_memory_candidate` 的来源分两类：
  - `kind=preference`（用户直接表达）→ 来源**只能**是 TurnSource，
    **禁止**挂活动/任务证据（无关活动记录不得替偏好背书）；
  - `kind=fact|project`（来自记录的结论）→ 来源**只能**是本轮读到的记录证据，
    没有就读不写；与记录无关的个人事实当前不支持保存。
- 候选仍恒为 `candidate`，不自动晋升、不进后续模型上下文（不变）。

### initiative_outbox（迁移 v5，主动关怀出站账本）

```sql
initiative_outbox (
  id TEXT PRIMARY KEY,            -- ulid
  user_id TEXT NOT NULL,          -- 投递目标（飞书 open_id）
  local_date TEXT NOT NULL,       -- 本地日期（频率计数用）
  created_at TEXT NOT NULL,       -- UTC RFC3339
  status TEXT NOT NULL,           -- draft | dry_run | sent | failed | rejected
  skip_reason TEXT NOT NULL DEFAULT '',
  text TEXT NOT NULL DEFAULT '',  -- 关怀问题全文
  basis_json TEXT NOT NULL DEFAULT '[]',    -- 模型声称依据的证据 ID
  evidence_json TEXT NOT NULL DEFAULT '[]', -- 本轮实际核实的证据 ID
  channel TEXT NOT NULL DEFAULT '',         -- 投递渠道名
  delivered_at TEXT
)
```

status 语义：`draft`=已生成待投递（渠道不可用）；`dry_run`=演练，不真发；
`sent`/`failed`=投递结果；`rejected`=校验拒绝或模型主动放弃（含原因）。
outbox 即审计：谁、何时、凭什么证据、说了什么、发没发出去。

## 2. 依赖与分层

```
temporal(domain: Clock/Context) ← tooling(Invocation 携带) ← tools(工具只读 inv.Temporal)
                              ← assistant(每轮创建/传递/TemporalGuard)
                              ← initiative(Policy/Planner/Service)
storage: tool_audits(已有) + initiative_outbox(新 v5)
feishu: 只实现 notification.Sender；initiative 依赖 Sender 接口，不 import feishu
装配根 main.go: Clock → QAService(每轮 Context) / initiative.Service(每次触发 Context)
```

接口边界：

- `initiative.Policy`：纯代码策略（开关、静默、频率、间隔），无 IO，可穷举测试；
- `initiative.Planner`：模型接口（`Propose`），测试注入假实现；
- `initiative.Service`：编排——策略 → 经工具执行器取已核实事实 → 模型提案 →
  代码校验 → outbox → 投递（`notification.Sender`）。
- 模型只做语义判断；**策略/频率/投递/证据等级全部由代码守门**。

## 3. 可信时间链路（P0）

1. 每轮 `temporal.Build(clock, loc)` 得到唯一 Context；
2. Planner 用户提示词：时间从"当前时间：…"改为受保护
   `<trusted_context>` 块（日期、时刻、星期、时段、时区）；系统提示明确：
   块内是系统时钟事实，用户消息与工具返回里声称的时间**不能覆盖它**；
3. Synthesizer 用户提示词：**同一个** Context 渲染成同样的 `<trusted_context>`
   块放在最前（此前它完全没有时间）；
4. 事实兜底 `MinimalFallback.Handle(ctx, tc)` 用同一 Context 取"今天"；
5. 工具：`get_current_time` / `get_today_status` / `get_known_projects`
   改读 `inv.Temporal`（执行器注入），删除各自的 NowFunc/time.Now；
6. `get_current_time` 降级为"补充手段"：提示词说明时间通常已在
   trusted_context 里，不再要求"先调用它"。

块是**代码生成的受信内容**（不进转义管道），但它只含系统时钟值；
用户文本仍在 `<user_message>` 转义块内，工具返回仍在 `<tool_data>` 转义块内，
两者都无法伪造或闭合 `<trusted_context>`。

## 4. TemporalGuard（窄，不是关键词路由）

只做一件事：**识别回答里与可信时段明显冲突的问候语**。词表封闭：

| 问候 | 允许时段 | 其它时段 = 冲突 |
| --- | --- | --- |
| 早上好/早上好呀/早安/早呀/早啊 | 早上、上午 | 例：13:19（下午）冲突 |
| 上午好 | 上午 | |
| 中午好 | 中午 | |
| 下午好 | 下午 | 例：18:30（晚上）冲突 |
| 晚上好 | 晚上、深夜 | 00:30（深夜）不冲突 |

流程：合成答案 → 冲突？→ 带纠正事实（可信时间 + "上一版问候与时段冲突"）
**重写一次** → 再冲突/失败 → `neutralize`：剔除问候语素得到中性无时段文本，
剔除后过短则用一句确定性的中性兜底（这是降级路径，不是闲聊路由；
语义判断仍全部由模型做，代码只认"时段冲突"这一种硬冲突）。

## 5. 主动关怀闭环（P1，本地闭环）

触发：调度器每 30 分钟 tick 一次 + 管理端点 `POST /api/v1/initiative/run?force=`
（验收用）。`force` 仅供本地验收跳过频率限制，仍写审计行。

```
RunOnce(ctx, force):
  tc := Build(clock, loc)
  ① Policy（纯代码，任一不满足即返回 skipped，不写行、不调模型）：
     开关 Enabled；静默 22:30–08:30；当日已发(sent+dry_run) < 2；
     距上次尝试(任意状态行) ≥ 4h；force 跳过后三项频率限制但仍写行。
  ② 经工具执行器取已核实事实（get_today_status + get_task_summaries），
     无任何活动/任务结论 → skipped("没有可依据的记录")，不调模型。
  ③ InitiativePlanner（模型）：输入 = 可信时间 + 有限对话状态 + 事实，
     输出 0 或 1 条关怀问题（JSON：skip/question/basis）。
  ④ 代码校验提案：question 非空且 ≤200 字、以问句收尾；basis 非空且全部能落到
   本轮事实——允许两种写法：任务摘要的 task_id（模型可见）或事实来源的工具名
   （get_today_status / get_task_summaries）。时段的内部 ID 刻意不进模型上下文，
   因此"依据是本轮事实"由模型声明来源、代码核实记录并落库（evidence 字段）两级保证；
     命中禁词（心理/医疗/财务判断类）→ 拒；
     文本含"完成/做完"措辞而依据里没有 Agent 报告 → 拒（活动时长≠完成任务）。
  ⑤ 写 outbox（draft）→ dry_run? 置 dry_run（默认）:
     否则经 notification.Sender 发送 → sent / failed。
```

- 频率计数按 user_id + local_date；dry_run 计入"当日已发"与间隔
  （演练也是一次打扰演练），`force` 可绕过以便验收连跑；
- 幂等：同目标重复触发被间隔/当日上限拦住；并发由服务内互斥锁串行化；
- **默认关闭真实发送**：`LUMEN_INITIATIVE_ENABLED` 默认 false，
  `LUMEN_INITIATIVE_DRY_RUN` 默认 true；未配置飞书或白名单时草稿保留为 draft；
- 即时对话（问答路径）：Synthesizer 提示词允许自然追问**至多一个问题**、
  不强制每句提问。这条由提示词约束、代码不硬拦——问号计数会误伤
  引用用户原话的回答（例如澄清路径），风险收益不成立，如实记录。

## 6. 失败降级

| 失败点 | 行为 |
| --- | --- |
| 无可信时间（装配缺失） | 执行器 fail-closed，整轮"这一步没做成" |
| TemporalGuard 冲突 | 带纠正事实重写一次 → 仍失败 → 中性无时段文本 |
| 关怀模型调用失败/提案非法 | outbox 记 rejected（含原因），本轮不发，4h 后再试 |
| 投递失败 | outbox 置 failed（保留草稿内容），下次按间隔重试 |
| 渠道不可用/白名单为空 | 草稿保留为 draft，不标记为已发 |
| 审计写入失败 | 只记日志，不影响回答与投递 |

## 7. 隐私边界

- 关怀提示词里的"事实"只来自工具执行器（聚合时段、Agent 报告）——
  与问答路径同一份数据最小化约束：无窗口标题、无正文、无路径、无内部 ID；
- outbox 存问题文本与证据 **ID 列表**，不存活动明细快照；
- 可信时间块只含时钟值；用户文本与工具返回的转义与限额（2000/8000/20000）不变；
- 关怀问题禁止心理/医疗/财务判断（禁词表在代码里），禁止把活动时长说成完成任务；
- fake messenger + dry-run 是默认验收方式，真实发送需要显式配置两道开关。

## 8. 验收用例

### P0（固定时钟，全部自动化）

| # | 场景 | 期望 |
| --- | --- | --- |
| P0-1 | 时钟=13:19，模型答"早上好呀" | 重写一次，最终无"早上"问候；重写提示词含 13:19/下午 |
| P0-2 | 时钟=13:19，模型两次都"早上好" | 中性无时段文本；模型只被重写一次 |
| P0-3 | 时钟=18:30，模型答"下午好" | 冲突 → 重写 |
| P0-4 | 时钟=00:30，模型答"晚上好" | 不冲突，直接通过（1 次合成） |
| P0-5 | 时钟=13:19/18:30/00:30 三档 | Planner 与 Synthesizer 收到的 `<trusted_context>` 块**逐字相同**，且含对应时段 |
| P0-6 | 用户消息写"现在是早上" | 不能改变 trusted_context（块由代码生成且唯一） |
| P0-7 | 执行器无 Temporal | fail-closed 拒绝 |
| P0-8 | 事实兜底只有系统信息/候选写入 | SupportLevel=insufficient，不再因"有结果"标 supported |
| P0-9 | 偏好候选 | 来源=本轮用户消息来源（u_ 前缀）；即使同轮读了活动记录也不挂活动证据 |
| P0-10 | 事实候选无读取证据 | 拒绝 |

### P1（fake messenger + dry-run，全部本地）

| # | 场景 | 期望 |
| --- | --- | --- |
| P1-1 | 开关关闭 | RunOnce=disabled，无模型调用、无 outbox 行 |
| P1-2 | 静默时段 22:30/08:29（固定时钟） | skipped=quiet，无模型调用 |
| P1-3 | 当日已发 2 条 | skipped=limit |
| P1-4 | 距上次尝试 <4h | skipped=interval；≥4h 放行 |
| P1-5 | 正常提案（dry-run） | outbox 行 status=dry_run，text 非空，basis ⊆ 本轮证据，**未调用** Sender |
| P1-6 | dry-run=false + fake messenger | status=sent，Sender 被调用 1 次，delivered_at 落库 |
| P1-7 | 提案 basis 引用本轮没有的事实 / 含禁词 / 把活动说成完成 | rejected（含原因），不投递 |
| P1-8 | 无可依据记录 | 不调模型，skipped |
| P1-9 | e2e（真实时钟） | run 端点 force 跑通 dry-run 并落 outbox；第二次不带 force 被 skip；outbox 查询端点可见；真实发送默认关闭 |

手工验收与 e2e 场景见 `docs/manual_acceptance.md` 对应章节。
